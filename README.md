# ADB-control — обслуживание парка рекламных LED-экранов (T982 / Android 11)

Набор скриптов для установки и снятия защиты на рекламных LED-экранах
(Amlogic T982 «Droidlogic», Android 11, прошивка userdebug, root через
`adb root`), а также для снятия диагностических логов по ADB.

Разработано под реальный профиль отказов парка: гибель драйвера Wi-Fi
AIC8800 (cmd queue) — скан умирает, соединение рвётся, самовосстановления
нет, помогает только перезагрузка. Подробности — в разделе «Как работает
watchdog» и в changelog v2.

## Требования

| Что | Зачем |
|---|---|
| Прошивка **userdebug** (test-keys) | `adb root` — все скрипты работают от root |
| SELinux **permissive** | сервис init и shell-команды без ограничений |
| adb.exe рядом со скриптами или в PATH | автопоиск в `_adb_target.bat` |
| Скрипты репозитория в исходном формате строк | `.sh`/`.rc` — **LF**, `.bat` — **CRLF**; следит `.gitattributes` |

## Состав

| Файл | Назначение |
|---|---|
| `install.bat` | Установка: root → remount /vendor → push скриптов → проверка формата LF → перезагрузка → контроль запуска сервисов |
| `check.bat` | Статус: PID-файлы, живость процессов, логи, счётчики, сервис, ADB, SELinux |
| `harden.bat` | Защита: гарантирует живость watchdog/cleaner → отключает сетевой ADB (port 0) → перезапускает adbd |
| `enable_network_adb.bat` | Обратное включение сетевого ADB (по USB: `enable_network_adb.bat usb`) |
| `deploy.bat` | Полный цикл: install → check → harden |
| `reinstall.bat` / `uninstall.bat` | Полная переустановка / удаление |
| `network_watchdog.sh` | Сторож сети (см. ниже) |
| `cache_cleaner.sh` | Очистка кэша 10-го и 20-го числа |
| `led_startup.sh` + `led_monitor.rc` | Автозапуск при загрузке: старт скриптов через 90 c после boot_completed + отключение сетевого ADB |
| `Снятие логов.bat` | Диагностика: снимок системы, кольцевые логи на устройстве, монитор инцидентов на ноутбуке |
| `_adb_target.bat` | Общий выбор устройства (аргумент `IP`, `IP:port`, `usb`, serial или меню) |
| `Инструкция к FullLogger.md` | Методика снятия логов (в репозиторий не входит, лежит рядом у эксплуатанта) |

## Быстрый старт

```bat
deploy.bat 192.168.100.101        :: Wi-Fi по IP (порт 5555 по умолчанию)
deploy.bat usb                     :: первое USB-устройство
```

или по шагам: `install.bat <цель>` → `check.bat <цель>` → `harden.bat <цель>`.

После `harden.bat` устройство недоступно по сети. Для обслуживания:
подключить USB и выполнить `enable_network_adb.bat usb`.

## Как работает watchdog (v2.1)

Лестница восстановления — от мягкого к жёсткому:

1. **Автодетект шлюза** (без хардкода): `ip route get 1.1.1.1` — на
   Android 11 в main-таблице `ip route` нет default (netd держит маршруты
   в per-network таблицах), поэтому надежен только route get. Шлюз
   кэшируется в `gateway.txt`: при смерти драйвера маршрут исчезает из
   таблицы, а адрес из кэша остаётся — это ровно тот случай, когда
   вмешательство оправдано. Если экран переехали в другую сеть, при
   неудачных пингах шлюз перепроверяется по живому маршруту и кэш
   обновляется (счётчики сбрасываются — ребутов исправному устройству
   не будет).
2. **Пинг шлюза** (не 8.8.8.8!). 3 неудачи подряд (≈2 мин) →
   `svc wifi disable/enable` (до 3 раз, экран не гаснет, контент
   локальный).
3. Рестарты Wi-Fi не помогли → **reboot** (до 3 раз подряд; счётчик
   персистентный в `reboot_counter.txt`, сбрасывается при первом
   успешном пинге).
4. Лимит ребутов исчерпан → только журнал, «ждём сеть».
5. **WAN (8.8.8.8) недоступен при живом шлюзе** → только запись в лог,
   БЕЗ ребута: это авария 4G-модема/провайдера, перезагрузка экрана
   её не лечит, а контент локальный.
6. **Раз в час — контроль сканера**: `cmd wifi list-scan-results` при
   живом соединении. «0 сетей» дважды подряд — предвестник смерти
   драйвера AIC8800 → предупредительный рестарт Wi-Fi (до 3), затем
   ребут.

Журналы и счётчики — в `/data/local/tmp/scripts/`:
`watchdog.log` (ротация 250 КБ), `watchdog.pid`, `reboot_counter.txt`,
`gateway.txt`; cleaner: `cache_cleaner.log`, `cache_cleaner.pid`,
`last_clean_day.txt`.

## Changelog v2.2 (фикс «The filename … is incorrect» и ввод порта)

**Причина ошибки на Windows 11:** внутри `for /f` команда исполняется
через `cmd /c`, который при старте с кавычки срезает крайние кавычки.
Строки вида `'"C:\...\adb.exe" -s "IP:5555" shell …'` (4 кавычки) после
срезания превращались в мусор: `…adb.exe" -s "IP:5555 shell …` →
"The filename, directory name, or volume label syntax is incorrect"
или молча пустой вывод. Из-за второй формы `:wait_boot` никогда не
видел `sys.boot_completed=1` — install.bat всегда досиживал таймаут
180 с и просил IP вручную.

**Исправление:** каталог adb добавляется первым в PATH процесса
(`_adb_target.bat`), и во всех `for /f` adb вызывается **без кавычек**:
`in ('adb -s "%DEV%" shell …')`. Проверено тестом на Windows 11:
старые формы падают/молчат, новая — возвращает данные.

**Ввод порта:** во всех приглашениях ручного ввода IP можно указывать
`IP:порт` (без порта — берётся текущий PORT, по умолчанию 5555):
- `_adb_target.bat :ASK_IP` — подсказка в приглашении;
- `install.bat :ask_new_ip` — подсказка; `:save_reconnect_info`
  запоминает и порт (`OLD_PORT`), `:find_new_ip` переподключается на
  прежний `IP:PORT`, `persist.adb.tcp.port` ставится на текущий порт
  (а не захардкоженный 5555), `:apply_new_ip` дополняет ввод
  текущим портом.

**Репозиторий:** добавлен `_adb_target.bat` (был на GitHub, но
отсутствовал в клоне — install.bat без него несамодостаточен).

## Changelog v2.1 (по обсуждению автодетекта шлюза и зависания USB)

**network_watchdog.sh**
- Автодетект шлюза переделан на `ip route get 1.1.1.1` + grep/cut
  (awk в toybox Android 11 нет; в main-таблице `ip route` default
  отсутствует — прежний детект молча возвращал пустоту и работал
  только fallback 192.168.100.1).
- При неудачных пингах шлюз перепроверяется по живому маршруту:
  устройство, переехавшее в другую сеть, переключается на новый
  шлюз без лишних ребутов.

**install.bat**
- Лечится зависание «Ожидание загрузки устройства» по USB
  (adbd в цикле FUNCTIONFS_BIND не поднимает транспорт, и
  wait-for-device/shell висят вечно): `:wait_boot` сначала опрашивает
  `adb devices` (не блокируется), getprop — только для устройства в
  состоянии device.
- Автопоиск устройства после ребута: прежний IP → ping-sweep + arp
  по MAC в подсети /24 → ручной ввод. Перед каждым ребутом
  запоминаются IP/подсеть/MAC и ставится `persist.adb.tcp.port=5555`
  (порт не слетает после ребута; led_startup.sh/harden.bat позже
  отключают ADB как обычно).
- В usb-режиме после ребута `wait-for-device` заменён на
  `wait_boot 60` с понятной ошибкой.

**led_monitor.rc** — возвращён `seclabel u:r:su:s0`: домен существует
на userdebug-прошивках парка и остаётся permissive даже при
enforcing SELinux.

## Changelog v2 (по анализу логов парка)

**network_watchdog.sh**
- Фикс само-блокировки после ребута: проверка дубля теперь сверяет
  `cmdline` процесса — прежний lone `kill -0` давал ложное «уже
  запущен» при переиспользовании номера PID после перезагрузки.
- Триггер — пинг шлюза вместо 8.8.8.8; WAN-недоступность только
  логируется.
- Лестница: рестарт Wi-Fi → ребут (раньше ребут был единственным
  действием).
- Часовой контроль сканера (предвестник гибели драйвера).

**cache_cleaner.sh**
- Фикс no-op: `find -exec rm -rf {}/*` не работал (глоб не
  раскрывается без shell) — теперь `find … -exec sh -c 'rm -rf
  "$0"/*' {} \;`, очистка реально выполняется.
- Проверка дубля со сверкой cmdline (как в watchdog).

**install.bat**
- Проверка rw /vendor через `/proc/mounts` + `findstr` — замена и
  конвейеру `mount | grep | find` (ломался от GNU find в PATH Windows),
  и `mountpoint -w` (флага `-w` в toybox нет — всегда падал).
- `:wait_boot` без `wait-for-device` (тот висел вечно при недоступном
  устройстве — таймаут был недостижим); код возврата 2 = «не
  отвечает» → в wifi-режиме запрос нового IP вместо ложной ошибки.
- Сравнение `sys.boot_completed` по первому символу — adb shell
  присылает CRLF, точное сравнение с "1" не срабатывало никогда.
- Оживлена проверка CR на устройстве: `printf '\015'` (одинарный
  обратный слэш; прежние `'\\015'` давали литеральный текст «\015»,
  и проверка всегда молча «проходила»).

**harden.bat**
- Перед отключением ADB гарантируется живость watchdog и cleaner,
  при необходимости — перезапуск (в wifi-режиме после `ctl.restart
  adbd` устройства уже не достичь).
- После перезапуска adbd (usb) — повторный контроль обоих процессов.
- Проверки живости сверяют cmdline.

**check.bat** — проверки живости сверяют cmdline; добавлен просмотр
кэшированного шлюза.

**Снятие логов.bat** — удалён несуществующий `dumpsys dhcp`;
reconnect перенесён внутрь retry-цикла после `adb root`; блок снимка
вынесен в подпрограмму (не дублируется в п.6/п.8); `cd /d "%~dp0"` —
логи создаются рядом со скриптом.

**Репозиторий** — добавлены `.gitattributes` (LF/CRLF) и этот README.

## Известные ограничения

- `uninstall.bat`, `reinstall.bat`, `deploy.bat`, `enable_network_adb.bat`
  изменений v2 не содержат (наследие предыдущей версии, работают).
- Аварийный адрес шлюза по умолчанию — `192.168.100.1`: используется
  только до первого успешного `ip route get` (или если сеть ещё не
  поднялась). При другой адресации подсети правьте fallback в
  `network_watchdog.sh`.
- Автопоиск IP после ребута работает, если ПК и экран в одной
  подсети /24; MAC Wi-Fi постоянен для одного SSID (рандомизация
  Android 11 привязана к сети).
- `find /sdcard/etv/*` и `/sdcard/crashlog/*` удаляются cleaner'ом по
  решению эксплуатанта; при смене плеера проверьте, что папка etv
  не стала для него рабочей.
